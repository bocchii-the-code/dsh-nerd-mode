# Study-plus defaults live in host settings, not in the prompt text

Status: accepted, 2026-10-28.

`study-plus` carries user-adjustable behavior: whether a session opens with a Recall Session (and whether a skipped prerequisite gets its one-line recap), and how many unseen questions follow a lecture, in which form. The first draft of this feature appended the shipped defaults to the same `section` config string that already carries the overlay text. That approach fails for three reasons: the text is static per plugin load, so a change needs a remount; the user-layer override would force a user to restate the whole prompt to change one number; and the Settings UI needs a schema to project editable volatile fields, which a plain string does not provide.

The plugin now exports a Schemastery `Config` alongside `apply`. `section` stays required and non-volatile: it is prompt text, and swapping it must remount the plugin. The three behavior fields — `recallSessionEnabled` (boolean, default `false`), `unseenQuestionCount` (integer 0–10, default `3`), and `unseenQuestionType` (`short-answer` | `multiple-choice` | `mixed`, default `short-answer`) — are marked `.volatile()`, so Cordis commits an edit into the running reference without a restart and the host settings service exposes exactly those fields to the client. The page registers one root `settings.section`, not a Plugins-page tab, so the two behavior groups live in the Settings window beside the other sections.

The saved values join the system prompt at request time: the `study:policy` section renderer reads `.get()` on each volatile field, stamps the result per tracked invocation in a WeakMap so one `/study-plus` session keeps one consistent default even if the profile changes mid-session, and appends a short defaults block only when the current turn carried a direct `/study-plus` command or a completed `skill` tool call for `study-plus`. Ordinary `/study` turns and non-teaching requests see only the base overlay.

Alternatives. Constants compiled into the prompt string were rejected: no user-facing edit. A persisted skill-file edit was rejected: the skill is shipped content and a profile default would fork it per installation. A client-only preference in localStorage was rejected: it would not reach the host's prompt renderer and would not survive another profile. Exposing the whole `section` string through the Settings page was rejected: the page would invite prompt drift and lose the patch-file review path.

Consequences. The plugin gains a peer dependency on `@deepseek-ai/schemastery`, which resolves to the host package through the loader's peer-aware lookup. The settings service can refuse a write when the active patch is overridden by a home patch or a command-line overlay, and the page must surface that as a save error. A count of 0 changes the evidence rule for `fluent` in a tracked session (Teach-back alone suffices), which the skill text and the glossary state explicitly.
