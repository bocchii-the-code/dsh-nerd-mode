# Teaching is not evidence, but it is a state

A session that ended after the lecture and before the questions used to leave its concept at `new`. Nothing distinguished a concept the learner had never seen from one the tutor had just taught. The next session taught it again from zero, and the record said nothing had happened.

`in_process` fills that gap. The tutor writes it at the start of Teach, before the first paragraph, and only when the row is `new`. The next verdict clears it. A `shaky` or `fluent` row is never overwritten, because a failure or a pass is evidence and the marker is not.

That exception is the cost. The skill's first rule says only produced work changes the record. `in_process` changes it on the tutor's action. The rule survives with one named exception, and the state claims nothing about knowledge. It carries no date, because the date column is `Last evidence`, and its note reads `taught, no verdict`.

Writing at the end was rejected: the session that dies is the one that never reaches Record. Dating the teaching was rejected: it would make the column mean two things. Partial evidence was rejected: it invents a pass bar below the existing one. The value is named `in_process` rather than `taught`, because it describes the row as work in progress. The glossary fixes the literal.

Consequences. A crashed session writes no log block, so an undated row is the only trace. The next session repeats the lecture in full, then asks the three unseen questions. A defer is not a crash, because the log records it, so the tutor says what remains and offers the questions before repeating the lecture. The state satisfies no prerequisite, so dependents stay blocked. When no target is set, steering offers the unfinished concept against a lower-numbered `new` one and lets the learner choose.
